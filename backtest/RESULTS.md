### 1.2 롤링 오리진

독서 이력 38건을 읽은 시각 오름차순으로 정렬하고

```
for i = 10 .. 37:
    시드   = entries[0 .. i-1]      (그 시점까지 읽은 전부, 반응 가중치 + 시간 감쇠)
    정답   = entries[i]             (바로 다음에 읽은 것 하나)
    컷오프 = entries[i-1].read_at
    그래프 = 컷오프로 시간 검열한 스냅샷
```

**폴드 28개.** 후보 풀은 모든 방법이 공유한다: 검열된 그래프에서 시드로부터 무방향 3홉 이내, 이미 반응한 노드 제외.

시드 벡터와 PPR 은 `safari.html` 의 계산을 그대로 옮겼다.

```
s[i]  = w(반응) × 0.5^(경과일 / 반감기),   w = { 좋아요 2, 읽음 1, 스킵 -1 }
        경과일 = (컷오프 - read_at) / 1일,  |값| 합으로 정규화
p     = 0.15·s + 0.85·W·p        무방향 인접, 차수로 균등분할, 45회 멱반복
score = p[i] / max(deg(i), 1)^허브지수
```

> 참고: `README.md` 의 "추천 계산" 절은 감쇠를 `0.94^(경과)` 로 적어 두었지만, 이는 항목 인덱스 기반이던 옛 방식이다. `safari.html` 과 이 백테스트는 둘 다 경과 **일수** 기반의 `0.5^(경과일/반감기)` 를 쓴다. README 의 독서 이력 절에 적힌 식이 실제 구현과 일치한다.

### 1.3 시간 검열

컷오프 T 에서 `publication_date > T` 인 노드를 제거하고, 양 끝 중 하나라도 사라진 엣지를 제거한다. 인용 엣지의 시각은 인용하는 쪽 논문의 출판일이므로 인용하는 쪽이 사라지면 엣지도 함께 사라진다.

- **조건 A**(OpenAlex)는 실제 `publication_date` 를 쓴다.
- **조건 B**(손 그래프)는 날짜가 없어 **연도로 근사**한다. `연도 > 컷오프 연도`인 노드를 제거한다.
- **조건 S**(Semantic Scholar)는 조건 A 와 같이 실제 `publicationDate` 를 쓴다. 날짜가 비어 있는 2편(`bert`, `gpt2`)은 검열에서 항상 살아남는다.

### 1.4 지표

| 지표 | 정의 |
|---|---|
| MRR | 정답 순위의 역수 평균. **도달 불가 폴드는 0 으로 세고 전체 28폴드로 나눈다** |
| MRR\* | 도달 가능한 폴드만 놓고 계산한 참고값 |
| recall@10 / @50 | 정답이 상위 k 안에 있으면 1. 역시 도달 불가는 0 |
| 도달 불가 비율 | 정답이 후보 풀에 없는 폴드의 비율 |
| 무작위 순열 기대치 | 풀 크기 P 에서 정답이 균등분포일 때 `E[1/rank] = H_P / P`, `recall@k = min(k,P)/P`. **이 눈금 위에 있어야 그래프 계산이 값을 한 것이다** |

산포는 폴드별 역순위의 표준편차(±sd)와 정답 순위의 사분위(Q1~Q3)로 함께 낸다. 폴드가 28개뿐이라 평균만으로는 못 믿는다.

## 2. 커버리지

### 2.1 결과

| 항목 | 값 |
|---|---|
| 대상 | 78편 |
| **해소 성공 (제목 또는 arXiv id 로 검증)** | **76/78 (97.4%)** |
| 연도(±1년)까지 동시 통과 | 75/78 (96.2%) |
| arXiv id 로 확증 (DOI/랜딩 URL 에 arXiv id 실재) | 72/78 (92.3%) |
| 그중 **제목이 아예 다른 논문 것** (F1 < 0.6) | **8/76** (그중 실질 오염 6건, 아래 2.4) |
| **제목만으로 재판정** (arXiv id 확증을 빼고) | **68/78 (87.2%)** |
| **제목 + 연도로 재판정 (가장 보수적)** | **67/78 (85.9%)** |

해소 판정은 **arXiv id 확증이 제목 검증을 덮어쓰도록** 되어 있다(`fetch-openalex.mjs` 의 `titleOk = arxivConfirmed || (f1 >= 0.6 && coverage >= 0.75)`). 식별자가 맞으면 제목이 달라도 통과시킨다는 뜻이다. 그래서 **"97.4%" 는 식별자 기준 커버리지이고, 제목까지 맞는 것만 세면 85.9% 다.** 두 수치 모두 적는 이유는 2.4 에서 드러난다.

검증 방식은 **제목 토큰 F1 + 질의 제목 커버리지 + 연도 + arXiv id 실재 확인** 네 겹이다. `PAPERS` 의 제목이 `Exploring the Limits of Transfer Learning (T5)` 처럼 축약된 경우가 있어 정확 일치만으로는 잡히지 않는다. 제목 토큰 F1 분포는 0.6 이상이 68건, 0.6 미만이 8건이다.

### 2.2 해소 실패 2편

처음에는 4편이 실패했으나, 일일 예산이 회복된 뒤 제목 검색 폴백(`title_search_fallback`)을 돌려 2편을 추가로 해소했다.

| node_id | 최종 상태 | 사유 |
|---|---|---|
| `gpt2` | **실패** | arXiv id 자체가 없고(`""`), 제목 검색 결과도 0건 |
| `dsr1` | **실패** | arXiv DOI 조회 404, 제목 검색 결과도 0건 |
| `gpt4` | 해소됨 | arXiv DOI 조회는 404 였으나 제목 검색으로 W4327810158 (2023-03-15) 확보 |
| `llama3` | 해소됨 | 마찬가지로 제목 검색으로 W7115097999 확보. **다만 날짜가 2025-12-26 으로 틀렸고 피인용 0** |

**추가로 해소한 2편 모두 `referenced_works` 가 0건이다.** 즉 커버리지는 올랐지만 그래프는 하나도 좋아지지 않았다. `llama3` 은 `attention` 에 이어 두 번째 날짜 오류 사례이기도 하다 (실제 2024-07-31).

### 2.3 날짜가 깨진 건 2편

| node_id | `PAPERS` | OpenAlex | 실제 |
|---|---|---|---|
| `attention` | 2017 | **2025-08-23**, 피인용 7133 | 2017년, 피인용 10만 이상 |

사용자가 먼저 관찰한 것이 맞다. 다만 **잘못 매칭된 게 아니라 레코드 자체가 깨져 있다.** OpenAlex 가 이 work(W2626778328)에 새 DOI(`10.65215/...`)와 2025년 날짜를 붙였고 피인용수도 실제의 5% 수준이다. 시간 검열을 실제 날짜로 돌리면 **가장 중요한 시드 논문이 2025년 8월 이전 모든 폴드에서 사라진다.** 조건 A 를 쓰려면 이런 건을 손으로 고쳐야 한다는 뜻이다.

### 2.4 더 나쁜 것: 제목 필드가 다른 논문 것으로 뒤바뀐 레코드가 6편 있다

제목 F1 이 0.6 미만인 8편을 전수 확인했다. 이 중 2편(`bigbench`, `dpo`)은 우리 `PAPERS` 쪽 제목이 축약형이라 F1 이 낮게 나온 것으로 **정상**이다. 나머지 **6편은 진짜로 깨져 있다.**

| node_id | 질의 제목 | OpenAlex `display_name` | `doi` | 출판일 | refs |
|---|---|---|---|---|---|
| `bert` | BERT: Pre-training of Deep Bidirectional Transformers | AI-Assisted Pipeline for Dynamic Generation of Trustworthy Health Supplement Content at Scale | `10.4230/lipics.cosit.2022.18` | 2018-10-11 ✅ | 55 |
| `ppo` | Proximal Policy Optimization Algorithms | Diagnosing Non-Intermittent Anomalies in Reinforcement Learning Policy Executions | `10.4230/oasics.dx.2024.16` | 2017-07-20 ✅ | 11 |
| `lora` | LoRA: Low-Rank Adaptation of Large Language Models | LoRA Fine-Tuning of a 3B Code LLM for Algorithmic Efficiency | `10.48550/arxiv.2106.09685` ✅ | 2021-06-17 ✅ | 57 |
| `cot` | Chain-of-Thought Prompting Elicits Reasoning in LLMs | BNAI, NO-TOKEN, and MIND-UNITY: Pillars of a Systemic Revolution... | arXiv DOI 일치 ✅ | 2022 ✅ | 있음 |
| `react` | ReAct: Synergizing Reasoning and Acting in Language Models | Distributing Accountability, Not Capability: Phase Separation... | arXiv DOI 일치 ✅ | 2022 ✅ | 0 |
| `cai` | Constitutional AI: Harmlessness from AI Feedback | Affective Coherence Monitoring for Transformer-Based Language... | arXiv DOI 일치 ✅ | 2022 ✅ | 0 |

**패턴이 일관된다. 출판일은 맞는데 `display_name` 이 전혀 다른 논문 것이다.** `lora` 는 DOI 가 정확히 `10.48550/arXiv.2106.09685`(LoRA 의 arXiv DOI)인데 제목은 "LoRA Fine-Tuning of a 3B Code LLM" 이다.

**단, `bert` 와 `ppo` 는 이 판정 자체를 오프라인에서 재확인할 수 없다.** 둘은 DOI 가 무관한 학회 DOI(LIPIcs/OASIcs)이고, `arxiv_confirmed` 판정의 근거였던 `locations[]` URL 을 캐시에 저장하지 않아 증거가 남아 있지 않다 (7절 한계 12번). 남은 정황 증거는 출판일이 정확히 arXiv v1 날짜와 일치한다는 것뿐이다: `bert` 2018-10-11, `ppo` 2017-07-20. 참고문헌 수(55, 11)도 그럴듯하다. **정황상 맞는 논문일 가능성이 높지만 확증은 아니다.**

영향 범위:

- **백테스트 결과에는 영향이 없다.** 그래프는 `work.id`·`publication_date`·`referenced_works` 로만 만들고 `display_name` 은 쓰지 않는다.
- **제품 코드에는 치명적이다.** 추천 카드에 OpenAlex 의 `display_name` 을 그대로 띄우면 76편 중 6편(7.9%)이 엉뚱한 제목으로 나간다. 제목은 arXiv API 나 자체 `PAPERS` 를 원천으로 삼아야 한다.

2.3 의 `attention` 날짜 오류와 합치면, **OpenAlex 레코드에서 신뢰할 수 있는 필드는 `id` 와 `referenced_works` 정도이고 `display_name`·`publication_date`·`cited_by_count` 는 전부 교차 검증이 필요하다.**

### 2.5 어느 해소 전략이 먹혔나

**중요**: 사용자가 관찰한 "arXiv DOI 는 hits 0" 은 **DOI 표기 형식 문제였다.**

| 전략 | 질의 형태 | 결과 |
|---|---|---|
| `doi_arxiv_url` | `filter=doi:https://doi.org/10.48550/arxiv.<id>` | **먹힌다.** 27/32 |
| `doi_arxiv_bare` | `filter=doi:10.48550/arxiv.<id>` | 27/32 (list 엔드포인트에서는 동작) |
| `entity_doi_arxiv` | `GET /works/doi:10.48550/arxiv.<id>` | **가장 잘 먹힌다.** 41편을 이걸로 해소 |
| `search` | `search=<제목>` | 27/29 |
| `title_search` | `filter=title.search:<제목>` | 24/30 |
| `title_search_year` | `filter=title.search:<제목>,publication_year:<연도>` | **20/30. 가장 나쁘다** |
| `title_search_fallback` | 위 DOI 전략이 전부 실패한 4편에만 제목 검색 재시도 | 2/4 (`gpt4`, `llama3`) |

채택된 전략 분포: `entity_doi_arxiv` 41편, `doi_arxiv_url` 27편, `title_search` 3편, `search` 3편, `title_search_fallback` 2편.

`title_search_year` 가 가장 나쁜 이유는 2.3 과 같다. **OpenAlex 의 `publication_year` 를 신뢰해 필터에 넣으면 오히려 정답을 걸러낸다.**

### 2.6 부수적이지만 운영에 직결되는 발견: OpenAlex 는 유료 쿼터제로 바뀌었다

1차 실행이 78편 중 33편에서 멈췄다. 429 응답 본문:

```
{"error":"Rate limit exceeded",
 "message":"Insufficient budget. This request costs $0.001 but you only have $0 remaining.
            Resets at midnight UTC.",
 "retryAfter": 80015}
```

응답 헤더 기준:

| 항목 | 값 |
|---|---|
| 일일 무료 예산 | `x-ratelimit-limit-usd: 0.1` ($0.10) |
| 검색(list) 요청 1건 | $0.001 → **하루 약 100건** |
| 단일 엔티티 조회 1건 | $0.0001 → **하루 약 1000건** |
| 리셋 | 매일 UTC 자정 |

`mailto` 를 붙여도, 빼도, 바꿔도 동일하게 429 였다. 예산은 IP 기준으로 보인다.

**제품 함의**: 78편에 대해 다전략 검색을 돌리면 약 390건이 필요해 무료 예산의 4배다. 반면 arXiv id 를 알고 있으면 `GET /works/doi:10.48550/arxiv.<id>` 로 **1편당 1건, 10배 싸게** 해소된다. 이 프로젝트의 노드는 전부 arXiv id 를 갖고 있으므로 **검색을 쓰지 말고 DOI 직접 조회만 쓰는 것이 맞다.** (`fetch-openalex-resume.mjs` 가 이 방식이고, 남은 44편 중 41편을 429 한 번 없이 받았다.)

### 2.7 같은 절차를 Semantic Scholar 에 돌리면

| 항목 | OpenAlex | Semantic Scholar |
|---|---|---|
| 해소 (식별자 기준) | 76/78 (97.4%) | **78/78 (100%)** |
| **제목 + 연도로 재판정 (가장 보수적)** | 67/78 (85.9%) | **75/78 (96.2%)** |
| arXiv id 확증 | 72/78 (92.3%) | 76/78 (97.4%) |
| 식별자는 맞는데 제목이 다른 레코드 | 8건 (그중 진짜 딴 논문 6건) | 3건 (**전부 같은 논문**, 아래) |
| 연도가 어긋난 건 | 1건 (`attention` 2025) | 0건 |
| 출판일이 비어 있는 건 | 0건 | 2건 (`bert`, `gpt2`) |
| 해소 실패 | `gpt2`, `dsr1` | 없음 |

**제목 검증에 걸린 3건은 OpenAlex 와 성격이 다르다.** `bigbench` 와 `dpo` 는 우리 `PAPERS` 쪽 제목이 부제를 뺀 축약형이라 F1 이 낮은 것이고, `dsr1` 은 Semantic Scholar 가 arXiv 판이 아니라 Nature 게재판 제목("DeepSeek-R1 incentivizes reasoning in LLMs through reinforcement learning", DOI `10.1038/s41586-025-09422-z`)을 돌려준 것이다. 세 건 모두 `externalIds.ArXiv` 가 우리 id 와 정확히 일치하고, 78편 전부를 눈으로 대조해도 **다른 논문이 붙은 레코드는 0건**이다. OpenAlex 의 "DOI 는 맞는데 제목은 무관한 글" 현상이 Semantic Scholar 에는 없었다.

`bert` 는 NAACL 판(2019)으로 잡혀 우리 연도 2018 과 1년 차이가 나지만 허용 범위(±1) 안이다.

해소 전략은 `arxiv_batch` 76편(요청 1건), `title_match` 2편(`lstm`, `gpt2`, 둘 다 arXiv id 가 없다)이다. **OpenAlex 때와 달리 논문마다 모든 전략을 전수 시도하지 않았다.** 처음엔 그렇게 짰는데 키 없는 공용 풀에서 13분에 6편밖에 못 가서, arXiv 확증과 제목 검증을 모두 통과한 건은 제목 전략을 생략하도록 바꿨다(`--all-strategies` 로 되돌릴 수 있다). 따라서 2.5 같은 전략별 성공률 표는 Semantic Scholar 에 대해서는 없다.

수집 통계: 요청 69건 · 429 응답 54회 · 재시도 53회. 네 번의 실행(본 수집 541초, 중단 후 재개 203초, 참고문헌 보충 2회)에 약 20분이 걸렸다. **키 없이는 1.1초 간격에도 429 가 나고 백오프(2초에서 64초까지 2배씩)가 누적된다.** 제품에서 쓰려면 API 키가 필요하다. 다만 `POST /paper/batch` 하나로 76편이 한 번에 왔으므로, 키가 있든 없든 arXiv id 를 아는 논문은 검색을 쓰지 말고 batch 로 받아야 한다는 결론은 OpenAlex 와 같다.

부수 발견: **`/paper/search` 와 `/paper/search/match` 는 `references` 필드를 돌려주지 않는다.** 제목으로 해소된 `lstm`·`gpt2` 가 참고문헌 0건으로 왔고, paperId 로 다시 조회하는 보충 단계(`--enrich`)를 넣어야 했다. `gpt2` 는 보충해도 빈 배열이 왔고(`referenceCount` 75 인데 목록 0건), `lstm` 은 두 번 다 429 로 실패했다(검색 응답의 `referenceCount` 는 48 이라 데이터는 있다).

### 4.1 읽는 법

**조건 A 는 여기서 끝난다.** 도달률 21.4% 는 "78.6% 의 폴드에서는 정답이 후보 목록에 아예 없다"는 뜻이다. 랭킹을 아무리 잘해도 recall 은 0.214 를 넘을 수 없다. 실제로 조건 A 의 모든 방법이 recall@50 = 0.214 로 똑같이 천장에 붙어 있다. **조건 A 는 알고리즘 비교에 쓸 수 없다.**

**조건 B 의 89.3% 는 좋아 보이지만 그대로 믿으면 안 된다.** 1홉 도달률과 3홉 도달률이 **정확히 같다**(둘 다 25/28). 즉 도달 가능한 정답은 전부 시드의 직접 이웃이다. 이건 그래프가 잘 만들어졌다는 뜻이 아니라 **`CITE_SRC` 가 이 독서 이력을 알고 있는 상태에서 손으로 작성됐다**는 신호에 가깝다. 6.2 에서 다시 다룬다.

도달 불가 3폴드는 전부 아티클(`a-kipply`, `a-scale`, `a-weng`)이다. README 가 적은 대로 인용 그래프에 붙을 통로가 없는 고립점이고, 이 백테스트에서도 끝까지 못 맞힌다.

### 4.2 시간 검열이 이 데이터에서는 무효다

**컷오프마다 제거되는 노드가 0개다.** 이유는 단순하다. mock 독서 이력이 2026-04 ~ 2026-09 인데 `PAPERS` 의 논문은 전부 2025년 이하다. 모든 논문이 모든 읽음 사건보다 먼저 나왔으므로, "미래 논문 드롭" 규칙이 걸릴 대상이 없다.

검열 로직 자체는 구현했고(`engine.mjs` 의 `censor()`), 실제 날짜가 붙는 순간 동작한다. 다만 **이 mock 데이터로는 시점 누수의 크기를 잴 수 없다**는 것이 정직한 결론이다. 그래서 조건 B' 를 따로 만들었다 (6.3 참조).

### 4.3 조건 S 는 도달률 문턱을 넘는다

**85.7% 는 손 그래프(89.3%)와 한 폴드 차이다.** 도달 불가 4폴드는 아티클 3건(`a-kipply` `a-scale` `a-weng`, 손 그래프에서도 불가)과 `mamba`(참고문헌 0건이라 고립) 하나다. 즉 실제 인용 데이터로 만든 그래프에서도 정답의 86% 가 시드 3홉 안에 들어온다. **"실제 원천으로는 그래프가 안 만들어진다"는 조건 A 의 결론은 OpenAlex 에 한정된 것이었다.**

다만 두 가지를 같이 읽어야 한다.

1. **1홉 도달률(82.1%)이 3홉(85.7%)과 거의 같다.** 손 그래프에서 본 "정답은 언제나 시드의 직접 이웃" 성질이 실제 그래프에서도 유지된다. 손 그래프 엣지의 72% 가 Semantic Scholar 에 실재하므로(3.3), 손 그래프 엣지를 따라 짠 mock 이력은 실제 그래프에서도 대부분 이웃 관계로 남는다. 이 수치는 여전히 **이력을 그래프 노드 목록에서 골라 만든 설계의 산물**이고(6.6), 실제 사용자의 도달률 상한은 아직 모른다.
2. **출판일 타임라인(S')에서는 78.6% 로 떨어진다.** 컷오프당 노드 13.5개가 실제로 제거되고, `llama3`·`dsv3` 가 추가로 도달 불가가 된다. 검열이 실제로 걸리는 유일한 실제 원천 조건이라, 시점 누수의 크기가 이 데이터에서는 대략 7%p (85.7 → 78.6) 라는 첫 추정치가 된다. 다만 S' 은 합성 타임라인이다(5.3 의 한계가 그대로 적용된다).

## 6. 해석

### 6.1 PPR 은 평균으로는 이겼다. 그런데 이긴 폭이 표본보다 크지 않다

주 조건에서 PPR 최고 조합은 MRR 0.158 로 최고 베이스라인 0.099 를 +0.058 이겼고, 무작위 순열의 2.4배다. 방향은 명확하다.

문제는 확실성이다. **폴드별 승패가 15승 10패 3무다.** 무승부 3개(양쪽 다 도달 불가)를 빼고 25폴드에서 15승 10패면 부호 검정 양측 p ≈ 0.42 다. **"우연히 이렇게 나올 확률"을 배제할 수 없다.** 폴드 28개, 그중 유효 25개는 이 크기의 차이를 확증하기에 부족하다.

게다가 5.1.1 에서 본 대로 **비교 기준을 폴드별 최선 베이스라인으로 바꾸면 12승 13패로 뒤집힌다.**

정직하게 쓰면: **PPR 이 베이스라인보다 낫다는 쪽으로 증거가 기울지만, 이 데이터로는 확정할 수 없다.** 평균 MRR 만 보고 "PPR 이 이겼다"고 제품 결정을 내리면 안 된다.

### 6.2 피인용수 베이스라인이 무작위보다 나쁘다는 것이 실은 가장 유용한 결과다

| | MRR |
|---|---|
| 피인용수 순 | 0.034 |
| 무작위 순열 | 0.067 |

**피인용수 순 정렬은 무작위 셔플보다 나쁘다.** 정답 순위 중앙값이 33위(Q1~Q3: 25~48)로, 63개 후보 중 아래쪽 절반에 몰려 있다.

이유는 명확하다. 사용자는 이미 유명한 논문을 읽었다. 다음에 읽는 것은 시드에 특이적인 후속 논문(`medusa`, `streaming`, `flash2`, `qwen2`)이고, 피인용수 순위는 이것들을 항상 바닥에 둔다. **"유명한 것부터 보여주기"는 이 문제에서 반생산적이다.** README 가 피인용 top-10 겹침률을 실시간으로 보여주는 설계는 옳았고, 겹침이 낮을수록 좋다는 방향도 맞았다.

한편 **`CITE_SRC` 가 이 독서 이력을 알고 작성됐을 가능성**을 배제할 수 없다. 근거는 4.1 에서 본 1홉 = 3홉 도달률이다. 손 그래프에서 정답은 언제나 시드의 직접 이웃이고, 이건 자연 발생한 인용 그래프에서는 보기 드문 성질이다. **조건 B 의 절대 수치(MRR 0.158, 도달률 89.3%)는 낙관적으로 편향돼 있다고 봐야 한다.** 방법 간 상대 비교는 같은 그래프 위에서 이뤄지므로 상대적으로는 덜 오염됐지만, 손 그래프가 PPR 이 잘 도는 모양으로 그려졌을 가능성 자체는 이 백테스트로 반증할 수 없다.

### 6.3 시점 누수는 이 데이터로 잴 수 없었다

README 가 걱정한 "6월에 읽은 것으로 8월 논문을 맞히는데 그 논문이 도달 가능한 이유가 9월 논문들이 인용해서일 수 있다"는 문제는, **이 mock 데이터에서는 애초에 발생하지 않는다.** 모든 논문(≤2025년)이 모든 읽음 사건(2026년)보다 먼저 나왔기 때문이다. 컷오프마다 제거되는 노드가 0개다.

검열 코드는 구현했고 실제 날짜에서 동작한다. 그러나 **"검열을 걸면 점수가 얼마나 떨어지는가"는 측정하지 못했다.** 이걸 재려면 독서 이력이 논문 출판 시기와 겹쳐야 한다. 조건 B' 가 그 대용이지만 합성이고, 최근성 베이스라인이 무효화되는 결함이 있다.

### 6.4 조건 A 는 억지로 돌릴 대상이 아니다

돌려는 봤고 표도 넣었지만, 도달률 21.4% 아래에서 나온 수치는 방법 비교에 쓸 수 없다. 원인은 랭킹이 아니라 데이터다.

```
2022년 이후 논문 참고문헌 보유율 2.4%
  → 76노드 중 50개가 고립점
  → 독서 이력 38건 중 29건이 그래프에 안 붙음
  → 도달률 상한 21.4%
  → 어떤 랭킹 알고리즘도 recall 0.214 를 못 넘음
```

**"참고문헌 데이터가 비어 있을 가능성이 크다"는 가설은 확인됐다. 다만 전면적이 아니라 2022년을 경계로 한 시간축 절벽이다.** 2021년 이전은 91% 가 멀쩡하다.

### 6.5 실제 그래프에서 PPR 이 최근성에 지는 이유는 셋 중 어느 것인지 아직 가릴 수 없다

수치는 분명하다. 같은 이력, 같은 코드, 그래프만 바꿨는데 PPR 최고 MRR 이 0.158 에서 0.087 로 떨어지고 최근성이 0.088 에서 0.107 로 오른다. 가능한 설명은 셋이고, 이 데이터로는 구분되지 않는다.

1. **그래프 밀도.** 평균 차수가 6.16 에서 12.44 로 두 배가 됐다. PPR 질량이 두 배 많은 이웃으로 퍼지고, 후보 풀도 넓어져 정답 순위 중앙값이 12 에서 21 로 밀린다. 손 그래프는 "이 이력에 맞는 엣지만 골라 그린" 희소 그래프였다는 뜻이다. 손 그래프에 없던 엣지 293개가 PPR 에는 전부 노이즈로 작용한다.
2. **날짜 해상도.** 조건 B 의 최근성은 연도밖에 몰라 같은 해 안에서는 피인용수로 동점을 깬다. 조건 S 는 일 단위 출판일을 쓴다. mock 이력이 시간이 갈수록 최신 논문으로 옮겨가도록 짜여 있어서, 정확한 날짜를 아는 최근성 베이스라인은 그 궤적을 그대로 따라간다. 최근성의 상승분(0.088 → 0.107)은 그래프가 아니라 날짜 필드가 만든 것일 수 있다.
3. **순환 논증의 해소.** 손 그래프와 mock 이력은 같이 설계됐다(6.2, 6.6). 그 결합이 PPR 에 유리하게 짜여 있었다면, 실제 그래프로 바꾸는 순간 그 이점이 사라지는 것이 당연하다. 이 경우 0.087 이 진짜 성적에 가깝고, 0.158 은 처음부터 허수였다.

셋 중 어느 것이 주원인이든 제품 결정은 같다. **손 그래프 백테스트로 정한 파라미터(deg^0.8, 반감기 90일)는 실제 그래프에서 다시 정해야 하고, "PPR 이 낫다"는 주장은 실제 독서 이력 없이는 할 수 없다.** 다만 2번 설명이 맞다면 최근성 베이스라인 자체가 mock 이력의 인공물이므로, 실제 이력에서는 순위가 또 바뀔 수 있다.

### 6.6 손 그래프 도달률 89.3% 는 순환 논증이다

조건 B 의 도달률 89.3% 는 이 문서 첫 판에서 조건 A 의 21.4% 와 나란히 놓여 "손 그래프는 충분하다"는 인상을 줬다. 그렇게 읽으면 안 된다. **mock 독서 이력 38건은 그래프 노드 목록에서 골라 만들었다.** 그러니 "내가 읽을 논문이 수집 범위 안에 있는가"는 설계상 항상 참이고, 89.3% 에서 빠진 10.7% 는 수집 범위 밖이라서가 아니라 아티클이라 인용 엣지가 없어서다. 후보 풀이 전체 노드의 71% 인 것도 같은 이유다. **이 백테스트는 랭킹만 쟀고 수집 기준은 한 번도 시험하지 않았다.**

조건 S 의 85.7% 도 같은 이력 위에서 잰 것이라 이 편향을 그대로 물려받는다. 실제 상한을 재려면 **읽을 목록을 먼저 정하고 그 뒤에 그래프를 수집**해야 한다. 그때 비로소 "몇 홉까지 가져올 것인가"가 파라미터로 측정된다.

## 7. 한계

수치를 쓰기 전에 반드시 같이 읽어야 할 것들이다.

1. **독서 이력이 mock 이다.** 38건 전부 가짜다. 여기서 나온 MRR·recall 은 "이 가짜 궤적을 얼마나 잘 재현하는가"이지 실제 사용자 행동에 대한 측정이 아니다.
2. **`CITE_SRC` 가 손으로 만든 그래프다.** 1홉 도달률이 3홉 도달률과 같다는 것은 정답이 항상 시드의 직접 이웃이라는 뜻이고, 그래프와 독서 이력이 같이 설계됐음을 시사한다. 조건 B 의 절대 수치는 낙관 편향이 있다.
3. **조건 B 의 시간 검열은 연도 단위 근사다.** 같은 해 안의 선후를 구분하지 못한다. 게다가 이 데이터에서는 제거되는 노드가 0개라 검열이 무효였다.
4. **폴드가 28개뿐이다.** 유효 폴드는 25개다. MRR 차이 0.058 은 폴드별 표준편차 0.2 대비 작아 통계적으로 확정되지 않는다. 부호 검정 15승 10패는 p ≈ 0.42 다.
5. **후보 풀이 그래프의 71% 다.** 조건 B 의 풀 중앙값 63.5 는 전체 89노드의 71% 다. 3홉 제한이 거의 아무것도 걸러내지 못한다. 따라서 **recall@50 은 무작위(0.707)와 거의 구분되지 않아 무의미하다.** 의미 있는 지표는 MRR 과 recall@10 뿐이다.
6. **`gpt2` 와 `dsr1` 은 끝내 못 찾았다.** `gpt2` 는 arXiv id 가 없고 OpenAlex 제목 검색에도 안 잡힌다(GPT-2 논문은 arXiv 에 올라간 적이 없다). `dsr1`(DeepSeek-R1)은 arXiv DOI 404, 제목 검색 0건이다. 2025년 발표 논문이 아직 색인되지 않은 것으로 보인다. 둘 다 독서 이력에 들어 있어(`dsr1` 은 폴드 36의 정답) 조건 A 에서 구조적으로 못 맞히는 폴드를 만든다.
7. **OpenAlex `publication_year` 를 신뢰할 수 없다.** `attention` 한 편이 2025년으로 잡혀 있다. 실제 날짜 기반 검열을 조건 A 에 적용하면 이 논문이 대부분의 폴드에서 사라진다. 조건 A 를 진지하게 쓰려면 날짜를 arXiv 원본으로 교차 검증해야 한다.
8. **아티클 3건은 구조적으로 못 맞힌다.** 도달 불가 3폴드가 전부 아티클이다. 개념(concept) 노드를 도입하기 전에는 이 10.7% 를 회수할 방법이 없다.
9. **모델 노드가 후보 풀에 섞여 있다.** `safari.html` 과 동일하게 8개 모델 릴리스 노드를 후보에 넣었다. 독서 이력에는 모델 노드가 한 번도 등장하지 않으므로 이들은 순수한 노이즈로 순위를 밀어낸다. 조건 A 에는 모델 노드가 없어 두 조건의 풀 구성이 다르다.
10. **OpenAlex 무료 예산이 하루 $0.10 이다.** 재현 실행은 하루 검색 100건 / 단일 조회 1000건 안에서만 가능하다.
11. **해소 판정이 arXiv id 확증을 제목 검증보다 우선한다.** `fetch-openalex.mjs` 는 `titleOk = arxivConfirmed || (f1 >= 0.6 && coverage >= 0.75)` 로 판정하고, `fetch-openalex-resume.mjs` 는 아예 `title_ok: true` 를 하드코딩한다(이 경로로 들어온 것이 41편, 전체 해소의 55%). 그래서 캐시의 `match.title_ok` 는 해소된 76편 전부 true 다. 제목만으로 다시 세면 68/78, 제목+연도로는 67/78 이다. (`title_only_ok` 필드를 새로 추가해 두었으니 앞으로는 그쪽을 보면 된다.) 이 백테스트는 제목을 쓰지 않으므로 결과에는 영향이 없지만, **캐시의 `title_ok` 플래그는 신뢰하지 말고 `match.f1` 을 직접 보라.**
12. **`locations[]` 를 캐시에 저장하지 않았다.** `arxiv_confirmed` 판정의 근거가 여기였는데 저장하지 않아 오프라인 재검증이 불가능하다. `bert`·`ppo` 두 건이 이 때문에 확증 불가 상태다. 다음 수집 때는 arXiv id 를 담고 있던 URL 자체를 증거로 남겨야 한다.
13. **조건 A 그래프에 자기루프가 1건 있었다.** `cot` → `cot` 이다. 제거 전 엣지 57개, 제거 후 56개이며 조건 A 의 PPR MRR 이 0.122 에서 0.121 로 미세하게 바뀐다(자기루프가 차수를 2 늘려 허브 보정에 영향을 줬다). 조건 B 에는 자기루프도 중복 엣지도 없어 영향이 없다.
14. **오매칭 6편이 조건 A 엣지의 일부를 오염시킨다.** 2.4 의 6편은 조건 A 의 56개 엣지 중 6개의 한쪽 끝이다. 다만 조건 A 의 근본 한계(2022년 이후 42편 중 참고문헌 보유 1편)는 오매칭과 무관하므로 "조건 A 를 못 쓴다"는 결론 자체는 바뀌지 않는다.
15. **Semantic Scholar 는 전략 전수 비교를 하지 않았다.** 키 없는 공용 풀의 429 때문에 arXiv 확증이 된 76편은 제목 전략을 생략했다. `--all-strategies` 로 다시 돌릴 수 있지만 키 없이는 시간이 많이 든다.
16. **Semantic Scholar 참고문헌 0건 5편 중 3편은 실시간 재확인을 못 했다.** `bigbench`·`dsv3` 는 API 로 `referenceCount` 0 을 다시 확인했고, `gpt4`·`mamba`·`llama3` 는 429 로 확인하지 못했다. 캐시의 batch 응답이 0 을 준 것은 확실하나 그것이 일시적 상태인지는 모른다. 독립 검증에서 엣지 5건 중 2건(`vllm`→`megatron`, `ring`→`gpt3`)도 API 로 실재를 확인했고 나머지 3건은 429 였다. **확인된 것 중 캐시와 어긋난 것은 없다.**
17. **조건 S 의 시간 검열도 이 데이터에서는 무효다.** 조건 A 와 같은 이유로 컷오프당 제거 노드가 0개다. S' 만 13.5개를 제거한다.
18. **조건 S 에서 `bert`·`gpt2` 는 출판일이 비어 있다.** 검열에서 항상 살아남고 최근성 베이스라인에서는 바닥으로 간다. 둘 다 독서 이력에 없어 정답이 되진 않지만 후보 풀에는 들어간다.
19. **Semantic Scholar 도 제목을 그대로 쓰면 안 된다.** 딴 논문은 아니지만 `dsr1` 처럼 학술지 게재판 제목으로 바뀐 것이 있다. 제목·날짜를 arXiv 원본으로 삼아야 한다는 결론은 유지된다.
