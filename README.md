## 왜 만드는가

주간 리포트를 LLM 에게 받으면 트렌디한 글을 요약해 주지만, **내가 그 주에 무엇을 읽었는지가 다음 주 리포트에 전혀 반영되지 않는다.** 리포트는 매주 같은 자리에서 다시 시작한다.

원하는 것은 셋이다.

1. **읽은 것이 남는다.** 논문·아티클·모델이 노드가 되고 내 반응이 같은 그래프에 얹힌다
2. **다음에 읽을 것을 이유와 함께 받는다.** "읽은 A 와 B 가 모두 인용하는 C" 같은 경로가 근거다
3. **내 반응이 다음 추천을 바꾼다.** 읽음·좋아요·스킵이 PPR 시드 가중치가 된다

```
읽음/좋아요/스킵  →  시드 가중치 갱신  →  PPR 재계산  →  추천  →  읽음 ...
```

## 두 화면

### 그래프 뷰 (`graph.html`)

분석용. 알고리즘이 무엇을 하고 있는지 드러내는 것이 목적이다.

- **렌즈** 5종: 내 것만 / 읽은 것 + 추천 / 인용 이웃 1홉 / 토픽별 / 전체
- **랭킹 방법** 4종을 즉시 전환: Personalized PageRank · 참고문헌 최빈 · 피인용수 · 최근성
- **허브 보정** 3단 (없음 / `deg^0.5` / `deg^0.8`)
- **시드 반감기** 3단 (30일 / 90일 / 감쇠 없음). 오래된 관심을 얼마나 끌고 갈지 정한다
- **피인용수 순위와의 top-10 겹침률**을 실시간 표시. 겹침이 높으면 그래프 계산을 할 이유가 없다는 뜻이다
- 추천 카드에 마우스를 올리면 그래프에서 "왜" 경로가 빛난다
- 문서 페이지(3단계 깊이, 인용 이웃), 주간 리포트 미리보기

### 논문 사파리 (`safari.html`)

같은 그래프·같은 알고리즘을 게임으로 감싼 것. **평가 도구를 겸한다.**

- 등불 반경 밖은 안개다. 다만 **PPR 추천 상위 8개만 안개를 뚫고 빛난다**
- 논문에 닿으면 조우. `1` 읽는다 · `2` 스킵 · `Esc` 지나친다
- 고르고 나면 **그래프가 그것을 몇 위로 두고 있었는지** 공개된다

시작할 때 캐릭터 4인 중 하나를 고른다. 능력은 **탐색에만** 영향을 주고 추천 판정에는 관여하지 않는다.

| 캐릭터 | 설정 | 능력 |
|---|---|---|
| 측량가 | 지도에 없는 길을 먼저 밟는다 | 비콘 인지 +50% |
| 등불지기 | 꺼진 인용을 다시 밝히는 사람 | 등불 반경 +30% |
| 전령 | 소문보다 한 걸음 빠르다 | 이동 속도 +28% |
| 야경꾼 | 어둠 속에서 더 멀리 손을 뻗는다 | 조우 반경 +50% |

스프라이트는 이미지 파일 없이 Canvas 2D 프리미티브로만 그린다 (`assets/sprites.js`).

| 내 선택 | 그래프 순위 | 판정 |
|---|---|---|
| 읽는다 | 상위 8위 안 | 일치 |
| 읽는다 | 순위 밖 | 불일치 · 추천이 놓쳤다 |
| 스킵 | 상위 8위 안 | 불일치 · 추천이 헛다리를 짚었다 |
| 스킵 | 순위 밖 | 일치 |

이 **판정 일치율이 곧 hit rate 다.** 주 단위로 기다리면 데이터 포인트가 1주에 1개지만, 조우 한 번에 판정 하나씩 쌓인다.

읽을 때마다 시드가 갱신되고 PPR 이 다시 돌아 빛나는 곳이 바뀐다.

## 독서 이력 (mock)

`data/reading-history.json` 에 **읽은 시각이 붙은** 38건이 들어있다. 2026-04-02 ~ 2026-09-03, 약 5개월치다.

```json
{ "node_id": "dsv3", "read_at": "2026-08-14T22:41:00+09:00",
  "reaction": "read", "source": "browser_history", "dwell_min": 38 }
```

**실제 기록이 아니라 mock 이다.** 다만 아무렇게나 만든 것이 아니라 백테스트 설계를 검증할 수 있는 형태로 짰다.

- 시각 분포가 현실적이다. 평일 저녁 20~23시 23건, 새벽 03~07시 **0건**. 간격은 최소 1.3시간 / 중앙값 4.7일 / 최대 9.1일이고, 하루에 3~4편을 몰아 읽은 날이 3일 있다
- 주제가 시간순으로 이어진다. MoE 계보(`moe → switch → gshard → mixtral → dsv2 → dsv3`)를 타고 내려가다가 5월에 어텐션 효율(`gqa → flash → flash2`)로 옮겨가고, 5/23 에 서빙 4편(`vllm → specdec → medusa → streaming`)을 몰아 읽는다
- 관심 밖 논문 4편(`ddpm`, `clip`, `whisper`, `ldm`)은 전부 `skipped` 다

**이게 있어야 최근성 감쇠가 진짜가 된다.** 이전에는 "몇 번째로 추가됐나"라는 인덱스로 감쇠를 계산했는데, 지금은 경과 일수로 계산한다.

```
decay = 0.5 ^ (경과일수 / 반감기)
```

반감기 30일이면 4월 독서의 가중치가 3% 로 떨어져 **가장 최근에 읽은 몇 편이 추천을 독식한다.** 90일이면 30% 가 남는다. 이것도 백테스트로 정해야 할 자유 파라미터다.

## 추천 계산

```
시드 벡터  s[i] = w(반응) × 0.94^(경과)        w = { 좋아요 2, 읽음 1, 스킵 -1 }
PPR        p = 0.15·s + 0.85·W·p              무방향 인접, 45회 멱반복
허브 보정  score[i] = p[i] / deg(i)^0.8
후보       이미 반응한 노드는 제외
근거       시드 → 후보 최단 경로 (무방향 BFS, 최대 4홉). 경로가 없으면 추천하지 않는다
```

### 허브 보정이 결과를 지배한다

같은 시드(MoE · 효율적 서빙 관심)에서 보정 강도만 바꾼 결과다.

| 방법 | 상위 3개 | 피인용 top10 겹침 |
|---|---|---|
| 피인용수 (베이스라인) | ResNet, Adam, BERT | 10/10 |
| PPR 보정 없음 | **GPT-3, T5**, DeepSeek-V3 | 4/10 |
| PPR + `deg^0.5` | DeepSeek-V3, GShard, Medusa | 2/10 |
| PPR + `deg^0.8` | **Mixtral, Medusa, DeepSeek-V3** | 0/10 |

보정 없는 PPR 은 허브로 수렴해 상위가 이미 아는 유명 논문으로 찬다. `deg^0.8` 을 걸면 시드에 특이적인 논문이 올라온다. **즉 진짜 쟁점은 "PPR 이 되느냐"가 아니라 "정규화 지수 하나가 순위를 통째로 뒤집는다"는 것이다.**

관찰된 부작용도 있다. **허브 보정은 degree-1 노드를 과보상한다.** 좋아요한 논문 하나에만 붙은 모델 노드가 1위로 튀어오른다. 허브를 누르면 반대쪽 꼬리가 열린다.

## 이 프로토타입이 답하지 못하는 것

- **읽음 이력은 가정한 시드다.** 실제 독서 기록이 아니다
- **인용 그래프가 오늘 시점 스냅샷이라 시점 누수가 있다.** 6월에 읽은 것으로 8월 논문을 맞히는데, 그 논문이 도달 가능한 이유가 "9월에 나온 논문들이 인용해서"일 수 있다
- 따라서 두 화면은 **"PPR 이 다른 답을 내는가"**까지만 답한다. **"그 답이 더 맞는가"**는 별개 문제다

## 백테스트 결과

`backtest/` 에 시간 검열된 롤링 오리진 백테스트가 있다. 재현하려면 `node backtest/run.mjs`.

독서 이력을 읽은 시각 순으로 세우고, 앞의 것들만 시드로 준 뒤 **바로 다음에 읽은 한 편**을 맞히게 한다.
시작점을 옮겨가며 28번 반복하고, 각 시점에서 그때까지 나오지 않은 논문은 그래프에서 지운다.
후보 풀은 모든 방법에 동일하고 중앙값 63.5개(전체 89노드)다.

### 랭킹 (손으로 만든 그래프 · 28폴드)

| 방법 | MRR | R@10 |
|---|---|---|
| **PPR deg^0.8 · 반감기 90일** | **0.158** | 0.393 |
| PPR deg^0.8 · 반감기 30일 | 0.145 | **0.464** |
| PPR deg^0.5 · 반감기 30일 | 0.141 | 0.393 |
| 베이스라인: 참고문헌 최빈 | 0.099 | 0.286 |
| 베이스라인: 최근성 순 | 0.088 | 0.143 |
| 베이스라인: 피인용수 순 | 0.034 | 0.071 |
| *무작위 순열 기대치* | *0.067* | *0.141* |

**"PPR 이 이겼다"고 쓰면 안 된다.** 평균은 최고 베이스라인의 1.6배지만, 폴드별 승패는 15승 10패 3무이고
기준을 폴드별 최선 베이스라인으로 바꾸면 **12승 13패로 뒤집힌다.** 28폴드는 이 크기의 차이를 지탱하지 못한다.

분명해진 것은 셋이다.

1. **허브 보정이 반감기보다 훨씬 크게 움직인다.** 지수를 0에서 0.8로 올리면 MRR +0.046, 반감기는 ±0.001
2. **피인용수 순 정렬은 무작위로 섞는 것보다 나쁘다** (0.034 대 0.067). "유명한 것부터"는 이 문제에서 반생산적이다
3. **스킵 가중치 -1 은 근거가 없다.** 0으로 두는 편이 낫다 (MRR 0.164 대 0.158)

`recall@50` 은 무작위 기대치가 0.707 이라 무의미하다. 후보 풀이 그래프의 71% 라서 그렇다.

### 데이터 원천: OpenAlex 는 못 쓰고, Semantic Scholar 는 쓸 수 있다

같은 78편을 두 원천에서 같은 절차(커버리지 → 참고문헌 밀도 → 도달률)로 쟀다.

| 측정 | OpenAlex | Semantic Scholar |
|---|---|---|
| 논문 해소 (제목·연도까지 맞는 것) | 67/78 · 85.9% | **75/78 · 96.2%** |
| 식별자는 맞는데 제목이 딴 논문인 레코드 | 6편 | **0편** |
| 참고문헌이 있는 논문 | 42.1% · 중앙값 0 | **91.0%** · 중앙값 49.5 |
| 2021년 이하 | 91.2% | 94.3% |
| 2022년 이후 | **2.4%** (2023년 21편, 2024년 10편 전부 0건) | **88.4%** |
| 그래프 엣지 / 평균 차수 | 56 / 1.47 | **485 / 12.44** |
| 독서 이력 38건 중 그래프에 붙는 것 | 9 | **33** |
| 도달률 (정답이 시드 3홉 안) | **21.4%** | **85.7%** |
| 도달률 (손 그래프, 참고) | 89.3% | 89.3% |

OpenAlex 는 2022년을 경계로 참고문헌이 사라져 도달률 21.4% 에서 끝났다. Semantic Scholar 에는 그 절벽이 없고,
손 그래프 엣지 266개 중 192개(72%)를 실제로 확인해 주며 손 그래프에 없는 엣지 293개를 더 갖고 있다.
남은 구멍은 대형 테크 리포트 5편(`gpt4` `llama3` `dsv3` `mamba` `bigbench`)의 참고문헌이 0건이라는 것이다.
키 없이는 429 가 잦아 78편에 약 20분이 걸렸다. 제품에서 쓰려면 API 키가 필요하다.

**그런데 실제 그래프 위에서는 PPR 의 우위가 사라진다.** 같은 이력, 같은 코드로 그래프만 바꾸면:

| | 손 그래프 | Semantic Scholar 그래프 |
|---|---|---|
| PPR 최고 (deg^0.8 · 90일) MRR | 0.158 | **0.087** |
| 최근성 순 MRR | 0.088 | **0.107** |
| 무작위 기대치 | 0.067 | 0.072 |
| PPR vs 최근성, 폴드별 | 15승 10패 | **10승 14패** |

허브 보정 방향(deg^0.8 이 여전히 상위)과 "피인용수 순은 무작위보다 나쁘다"는 것은 살아남았다.
"PPR 이 낫다"는 죽었다. 원인이 그래프 밀도(평균 차수 2배)인지, 일 단위 날짜를 얻은 최근성의 이득인지,
손 그래프와 mock 이력이 같이 설계된 순환 논증이 풀린 것인지는 이 데이터로 가릴 수 없다.

메타데이터 신뢰도는 원천별로 다르다. OpenAlex 는 arXiv DOI 로 정확히 조회되는데 제목이 전혀 다른 논문인
레코드가 76편 중 6편 있었다(예: `10.48550/arxiv.2201.11903` 은 Chain-of-Thought 논문인데 무관한 글의 제목이 붙어 있다).
Semantic Scholar 는 딴 논문은 없지만 `dsr1` 처럼 학술지 게재판 제목으로 바뀐 것이 있다.
**어느 쪽이든 제목과 날짜는 arXiv 를 원천으로 삼아야 한다.**

### 손 그래프 도달률 89.3% 는 믿으면 안 된다

mock 독서 이력 38건은 그래프 노드 목록에서 골라 만들었다. 그래서 "읽을 논문이 수집 범위 안에 있는가"가
설계상 항상 참이고, 빠진 10.7% 는 수집 범위 밖이라서가 아니라 아티클이라 인용 엣지가 없어서다.
Semantic Scholar 의 85.7% 도 같은 이력 위에서 잰 것이라 이 편향을 물려받는다.
**이 백테스트는 랭킹만 쟀고 수집 기준은 한 번도 시험하지 않았다.** 실제 상한은 아직 모른다.

### 아직 못 잰 것

- **실제 독서 이력.** 원천은 확보됐으니 다음 병목은 이것이다. 읽을 목록을 먼저 정하고 그 뒤에 그래프를 수집해야 도달률 상한과 홉 수 정책이 측정된다
- **시점 누수.** mock 이력이 2026년이고 논문은 전부 2025년 이하라 검열이 매 폴드 0개 노드를 제거한다.
  출판일 타임라인(합성)에서만 85.7% → 78.6% 로 떨어지는 것이 첫 추정치다
- **표본.** 28폴드로는 판정이 안 된다. 독서 이력이 100건쯤 쌓여야 한다
- **실제 그래프에서의 파라미터.** deg^0.8 · 반감기 90일은 손 그래프에서 정한 값이다. Semantic Scholar 그래프에서 다시 정해야 한다

## 실행

외부 라이브러리가 0개이고 빌드 단계도 없다. 다만 페이지가 `assets/sprites.js` 를
`<script src>` 로 부르므로 `file://` 직접 열기 대신 로컬 서버로 띄우는 편이 확실하다.

```bash
git clone https://github.com/sangho24/checkpoint-graph.git
cd checkpoint-graph
python3 -m http.server 8000
# http://localhost:8000
```

폰트만 Google Fonts 에서 받아온다(IBM Plex Sans KR · IBM Plex Mono · Do Hyeon). 오프라인이면 시스템 폰트로 대체된다.
